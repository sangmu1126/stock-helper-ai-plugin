# 거래시간 점검기: 공개 저장소 평가

기준일: 2026-11-18 · 대상 스킬: `market-hours-guard` · 기준표: `assets/calendar.demo.toml`

합성 저장소(`toy-broker`)에서만 맞는 도구인지 확인하려고, 국내 증권 API를 쓰는 공개 저장소 5곳에 스캔을 돌렸다. 처음 결과에서 오탐 유형을 찾아 스캐너를 고쳤고, 고친 뒤 남은 판정은 줄마다 직접 분류했다.

처음 769건 중 547건(71%)은 시각이 아니었다. 유형은 세 가지였다.

| 유형 | 예 | 고친 방법 |
| --- | --- | --- |
| API 문서의 코드 목록 | `0:전체,1:5미만,4:10~20`, `10:10일`, `5:15분전`, `10:10틱`, `02:10호가` | `N:숫자` 뒤에 단위(일·만·미만·틱·호가…)나 `~숫자`가 오면 코드로 본다. '분'은 실제 시각에도 붙어서("08:45분 경") 자릿수를 맞추지 않았거나 앞뒤 숫자가 같을 때만 코드로 본다 |
| 숫자 문자열 | 종목코드 `"005930"`, 연월 `end_dt='202606'`, 필드 번호 `'1223'`, 거래량 `fid_vol_cnt="1000"` | 바로 앞 이름이 시각 이름(time, hour, open, close …)일 때만 시각으로 본다. 날짜 이름(dt, date …)이면 뺀다. 예전에는 같은 줄 어디에든 "time"이 있으면(timeout, realtime) 시각으로 봤다 |
| 슬라이스 | `row[9:21]`, `rf1[11:40]` | 변수 바로 뒤 `[N:M]`은 시각이 아니다 |

고친 뒤 사라진 판정은 모두 위 세 유형이었다(줄 단위로 확인). 실제 시각이 함께 사라진 경우는 없었다. 고치는 중에 실제 시각이 빠진 경우("08:40 ~ 08:45분 경", `inqr_hour='100000'`)가 있었고, 규칙을 좁혀 되살렸다. 각 유형은 `tests/market_hours_guard/test_mhg_extract.py`에 회귀 테스트로 남겼다.

## 4. 실제 변경 누락: 폐지된 시간외 단일가 안내

2026-09-14 애프터마켓(16:00~20:00)이 열리면서 기존 시간외 단일가 매매(16:00~18:00)는 폐지됐다(근거 E12, [MARKET_HOURS_EVIDENCE.md](MARKET_HOURS_EVIDENCE.md)). 기준표에 이 변경을 폐기된 경계(`KRX_SINGLE_PRICE_CLOSE_UNTIL_20260913`, 18:00 → 애프터마켓 종료 20:00)로 넣고 다시 스캔했다.

| 저장소 | STALE | 내용 |
| --- | ---: | --- |
| 한국투자 open-trading-api | 9 | `국내주식 시간외 단일가(16:00~18:00) 시간대에 실시간호가 데이터 확인 가능합니다.` 등. 실시간 호가·체결가·예상체결 예제의 설명 문구(`examples_llm`, `examples_user`) |
| koapy | 1 | `16:00 ~ 18:00. 거래구분 62:시간외단일가` (2022년 이후 갱신 없음) |

- 한국투자 예제는 제도 변경 두 달 뒤(2026-11-16)에도 폐지된 세션 안내가 남아 있다. 이것은 **예제 설명 문구**이고, 증권사의 주문 처리 로직이 틀렸다는 뜻은 아니다.
- 같은 저장소의 "주간거래 10:00~18:00"(미국 주간거래)은 KRX 시간외 단일가가 아니므로 STALE이 아니라 AMBIGUOUS로 남았다. 문맥 단어로 구분한 결과다.

## 5. 한계로 드러난 것

**MATCH는 "기준표에 있는 값"이라는 뜻이지 의미 확인이 아니다.** MATCH 95건 중 37건은 값만 같았다.

- 일본 장 시작 09:00 ↔ KRX 정규장 시작
- 해외 예약주문 접수 10:00 ↔ 수능일 정규장 시작
- 홍콩 장 마감 17:00 ↔ 수능일 애프터마켓 시작
- 미국 봇 종료 16:30 ↔ 수능일 정규장 마감

그래서 MATCH도 Codex가 문맥을 확인하고 `mhg:` 주석으로 의미를 고정하는 흐름을 유지한다(SKILL.md 작업 순서).

**놓친 것 3종**

1. **1MB를 넘는 파일:** 키움 API 명세 JSON(3.8MB)의 "장시작(09:00) … 장마감(15:30)" 설명을 읽지 않았다. 예전에는 건너뛴 사실이 보고서에 나오지 않았다. 지금은 출력과 보고서에 `검사하지 않은 파일 N개`로 이름까지 표시한다.
2. **주변에 거래 단어가 없는 코드:** 한국투자 백테스터의 `if min_time <= "090000"`(정규장 시작에서 페이지 조회를 멈춤)은 시각으로 추출했지만, 같은 줄과 주변에 거래 관련 단어가 없어 보고하지 않았다. 문맥 판정을 넓히면 오탐이 늘어 그대로 두었다.
3. **데이터 집계 시각 안내:** `입력시간은 외국인 09:30, 11:20, 13:20, 14:30 …`은 거래시간 문맥으로 보지 않았다.

**이 평가 자체의 한계**

- 분류는 작성자 한 명이 했다.
- 놓친 것은 별도 정규식 검색과 대조해 찾은 것만 셌으므로, 전체 재현율은 측정하지 않았다.

## 6. 재현

```bash
git clone --depth 1 https://github.com/koreainvestment/open-trading-api /tmp/kis
python src/skills/market-hours-guard/scripts/mhg.py scan --repo /tmp/kis \
  --calendar src/skills/market-hours-guard/assets/calendar.demo.toml --out mhg-output/kis
```

저장소가 계속 바뀌므로 결과는 위 커밋 기준이다.
