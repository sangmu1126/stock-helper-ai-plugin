# 프로젝트 요약

## 한 문장 정의

카카오페이증권 관련 공개 자료를 바탕으로 거래시간 변경 누락과 잘못된 신용 안내를 점검하는 Codex 플러그인입니다. 사내용 스킬 2개와 일반 투자자용 스킬 1개로 구성되며, 별도 클라우드 배포·외부 AI API 키 없이 로컬 Python과 Codex로 사용합니다. 회사 공식 제품이 아니며 내부 코드·문서나 운영 개선 효과를 검증한 것은 아닙니다.

## 대상별 구성

| 대상 | 스킬 | 문제 (공개 근거) | 결과물 |
| --- | --- | --- | --- |
| 사내 개발자·QA | `market-hours-guard` | MTS 장애 42건으로 대형 12개사 중 공동 1위, 4년 연속 증가한 유일한 회사(금감원 자료). 거래시간 확대 진행 중, 애프터마켓 개장 첫날 SOR 시간 변경 과정의 장애, 수능일 같은 특수일 시간 변경 | 코드·설정의 거래시간 값을 승인된 기준표와 대조하고, Codex가 고친 뒤 경계 시각 테스트(특수일·휴장일 포함)로 확인 |

## 설계 원칙

- **판정은 결정적 코드, 이해·설명·수정은 Codex.** 문장 이해와 룰 JSON 작성은 Codex가 맡고, 스크립트는 형식 검증·정규화·규칙 계산·정책 판정을 수행합니다. 일반 초안 작성 자체가 플러그인만의 기능은 아닙니다.
- **공개 규칙과 제품 가정을 구분.** 기준표·신용 규칙의 출처 ID와 함께 `DEMO`, 업계 일반 계산식 같은 가정을 명시합니다. 출처가 있다고 모든 값이 회사 공식 규칙인 것은 아닙니다.
- **같은 기준을 공유.** 투자자용 런타임의 세션 설정과 사내용 거래시간 기준표, 투자자용 반대매매 계산과 사내용 규칙 점검이 같은 값을 쓰는지 테스트가 지킵니다.
- **확인할 수 없으면 통과시키지 않음(fail closed).** 공지되지 않은 특수일 세션, 휴장일 달력 범위 밖 날짜, 통화가 다른 가격 조건, 단일 시세로 확인할 수 없는 "N일 연속" 조건은 WAIT/STOP으로 둡니다.
- **로컬 전용.** 상태·감사 로그는 메모리 또는 로컬 파일, 정책은 로컬 JSON. 소스에 클라우드 SDK·AI API SDK가 없음을 테스트로 확인합니다.

## 데모 흐름

### 사내 개발자: "SOR 시간 변경과 수능일 시간 변경이 반영됐는지 점검해줘"

1. `mhg.py scan`이 합성 저장소에서 변경 누락(SOR 종료 15:30), 서머타임 미반영(미국 장 한국시간 고정값), 의미 불명확, 기준표에 없는 값을 찾습니다. 같은 15:30이라도 정규장 마감 알림은 정상으로 구분합니다.
2. Codex가 각 지점을 고치고 `mhg:` 주석으로 의미를 고정합니다.
3. 경계 테스트 50건 중 수정 전 17건 실패, 수정 후 50건 통과. Java 저장소용 JUnit 5 테스트로 만들어도 결과가 같습니다.
4. 다음 제도 변경 때는 새 기준표로 `impact`를 돌려 어느 줄이 MISMATCH가 될지 먼저 보고, CI는 SARIF로 PR 화면에 판정을 표시합니다. 수능일(정규장 10:00~16:30, 애프터마켓 17:00~20:00)과 연말휴장일(12/31)에 평소 시각을 쓰는 코드가 실패하는 것을 보여줍니다.

### 사내 상담 품질: "상담 스크립트와 앱 설정을 규칙과 대조해줘"

1. `margin_rule_check.py lint`가 "120% 이상이면 반대매매 없음" 같은 잘못된 안내, 유지비율 130%, D+3 반대매매 설정을 찾습니다(가상 자료에서 5건).
2. 고친 뒤 다시 돌려 0건을 확인합니다. 계산 코드에는 규칙 경계 테스트 21건을 생성해 연결합니다(연말 휴장일을 건너뛰는 반대매매 날짜 포함. 버그 있는 가상 모듈 9건 실패, 고친 모듈 21건 통과).

### 투자자: "담보비율 120%만 맞추면 반대매매 안 되지?"

1. 오해부터 바로잡습니다. 120%는 긴급 기준이고 140% 미만이면 이미 담보부족입니다.
2. 가상 계좌에서 7,600만 원을 입금해 127.2%가 되어도, 그날 120% 미만이었다면 당일 140% 회복 의무가 남아 다음 날 반대매매 대상입니다.
3. "테슬라 200달러 아래로 내려가면 알려줘"는 USD 가격 조건 초안으로 만듭니다. 사용자가 조건을 확인하면 로컬 SQLite에 등록하고 별도 감시 프로세스가 Windows 알림으로 제출합니다. 초안·등록·감시·OS 제출은 서로 다른 상태입니다. 담보비율 알림은 초안만 제공하며 계좌 상시 감시는 없습니다.

### 공개 원본 적용 사례 (0.7.1)

`market-hours-guard/scripts/public_example.py`로 한국투자증권 공식 예제 원본 14개를 고정 커밋·SHA-256에 대조합니다. 시간외 예제 7개에서 STALE 9곳과 UNMAPPED 9곳을 확인했고, 재무분석 예제 7개에서 종료 공지 대상 URL·TR ID·호출문 참조를 AST로 확인했습니다. 후자는 명시적 목록에 한정된 정적 대조이며, 실제 API 호출·차단·런타임 도달성은 검증하지 않았습니다. 공지 본문은 사용자 제공본이고 제목·게시일만 공식 포털에서 확인했습니다. 카카오페이증권 내부 코드 적용 사례가 아닙니다.

## 품질 지표

- pytest·ruff로 검증하며 생성된 JUnit 테스트는 CI에서 JDK로 실행합니다. 최신 로컬 결과와 과거 실행 기록의 버전·커밋은 루트 README 및 각 `summary.json`을 구분해 확인합니다.
- 가격 알림은 빈 작업 폴더에서 초안 → 확인 → 등록 → 감시 → Windows 알림 → Ctrl+C 중지까지 실행해 기록 ([docs/media/alert-flow](https://github.com/sangmu1126/stock-helper-ai-plugin/blob/main/docs/media/alert-flow/summary.json), 합성 시세). 미국 정규장에서는 실제 시세(시세 나이 0~2초)로 TSLA 알림이 발송됨 ([docs/media/us-real-alert](https://github.com/sangmu1126/stock-helper-ai-plugin/blob/main/docs/media/us-real-alert/summary.json))
- 공개 증권 저장소 5곳의 223개 판정을 한 명이 수동 분류한 결과 시각이 아닌 판정은 0건이었으나, 의미가 다른 MATCH는 20건 남았습니다. 전체 오탐률 0%나 재현율 보장을 뜻하지 않습니다. 한국투자 공식 예제에서 폐지된 시간외 단일가 안내 9곳을 확인했습니다([평가 문서](MARKET_HOURS_REAL_REPOS.md)).
- 합성 저장소·가상 계좌·가상 상담 자료로 수정 전후를 재현

## 현재 한계

- 사내용 스킬은 합성 자료와 증권업계 공개 코드로 검증했습니다. 회사 내부 원인 규명이나 실제 장애·민원 감소를 입증하지 않았습니다.
- 거래시간 점검기의 MATCH는 값이 기준표에 있다는 뜻이고 의미 확인은 아닙니다(공개 저장소에서 97건 중 37건이 값만 같았고, 수능일 기준을 고친 뒤 80건 중 20건).
- 담보비율 계산식은 공식 안내에 없어 업계 일반식을 쓰며, 출력에 "앱 표시값 우선"을 표시합니다.
- 휴장일 달력은 거래소가 공지한 2027년 말까지만 있습니다. 그 뒤 날짜는 판정하지 않거나(세션) 경고를 붙이므로(반대매매 날짜) 매년 갱신해야 합니다. 특수일은 공지가 확인된 날만 넣습니다.
- 카카오페이증권 주문·계좌 API에 연결하지 않았으며, 시세는 yfinance 또는 합성 공급자, 계좌는 사용자 제공 스냅샷을 사용합니다. 실주문은 하지 않습니다.
- 가격 알림은 PC에서 감시 프로세스가 켜져 있는 동안만 동작합니다. 자동 시작, 휴대폰 푸시, 계좌 담보비율 상시 감시는 없습니다.
- 국내(KRX) 종목은 실제 시세로 알림이 사실상 발송되지 않습니다. Yahoo의 KRX 시세는 20분 지연이고 애프터마켓 시세가 없어, 15초보다 오래된 시세로는 알리지 않는 기준에 걸립니다. 지연 가격으로 알리면 오판을 부를 수 있어 기준을 완화하지 않았습니다. 미국 종목은 정규장 중 시세 나이가 0~2초로 측정됐고 실제 시세 알림이 나갔습니다. 정규장 밖에서는 알리지 않습니다.
